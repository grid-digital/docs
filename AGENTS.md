# Cconnect developer documentation instructions

Before Mintlify changes, run `mint instructions` and read the relevant topic. Use `npx mint@latest instructions` if needed. Validate changes with `mint validate`, `mint broken-links`, and a local preview.

## Product and terminology

Cconnect connects company-owned support tickets, conversations, and channels. Company is the data boundary. A member is a human login; an integration credential is company-owned. Desk, Chat, and Call are product entitlements. A conversation is not a ticket.

## Content rules

Use version headings in the customer-facing changelog. Do not publish release dates, change dates, or last-updated dates on that page.

Use active voice, second person, concise sentences, sentence-case headings, and bold UI labels. Use MDX with title/description frontmatter and root-relative links. Do not invent endpoints, limits, availability, sandbox environments, or credential flows.

The OpenAPI specification is generated by `grid-digital/grid-connect-api`; regenerate it from Omni API rather than hand-editing it. Document only the customer contract. Never copy internal Swagger, provider callbacks, production secrets, session cookies, or real customer data into this repository.

Keep the API release preview label until backend deployment and availability have been verified. The developer portal does not grant API access. The customer application manages member sessions and credential administration.

Keep the playground in simple mode until the deployment and test environment are confirmed. Never claim a deployment succeeded without checking its live URL. Prefer a review branch/PR for changes targeting the connected production site.
